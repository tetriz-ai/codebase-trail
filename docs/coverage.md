# Coverage and boundaries

| Area | Covered in this preview | Boundaries |
| --- | --- | --- |
| Languages | JavaScript/TypeScript (including JSX/TSX), Go, Python, Java, Kotlin, Rust, Ruby, and C# have syntax parsers and architecture extractors. | Coverage focuses on imports, components, and selected relationships. It is not full compiler analysis or complete support for every framework in these languages. Other languages have no built-in architecture extractor. |
| Contracts and infrastructure | Protobuf imports, SQL table references, Kubernetes/Helm declarations, Docker Compose dependencies, and Terraform resources; selected npm, Python, Go, Cargo, .NET, Maven, and Gradle manifests. | Extracts supported declarations and patterns. Dynamic configuration and runtime behavior cannot be inferred reliably from these files alone. |
| Version control and hosting | Local Git checkouts for architecture practice; GitHub and authenticated GitHub CLI (`gh`) for PR practice. | PR discovery in the browser targets github.com and merged PRs authored by the signed-in user. GitLab, Bitbucket, and other VCS providers have no built-in PR integration. Local architecture practice needs no GitHub account. |
| Repository evidence | Source and declarations pinned to committed Git revisions; PR diffs and bounded repository context. | Uncommitted edits and untracked files are outside the committed snapshot. Incomplete, unresolved, or unsupported relationships can leave a scope without enough evidence to publish a question. |
| Model APIs | OpenAI-compatible Chat Completions endpoints, native OpenAI Responses, Anthropic Messages, and Vertex AI generateContent. Generation and review can use different models. | Compatibility is with these API contracts, not a guarantee for every model ID. Models must produce the required structured output and pass evidence and answer validation; credentials and model access are supplied by the user. |
| Model CLIs | Signed-in Claude Code (print mode) and Codex (exec mode). | Requires the corresponding CLI installed and authenticated locally. Available models depend on the CLI account; repository evidence is sent to its provider. |
| Learning | PR, LLD, service, and HLD questions; answer explanations, repeat avoidance, local history, feedback, and export. | The engine randomly chooses Foundational, Applied, or Systems for each candidate and tags the published question. All eligible relationships and service paths within the configured hop depth remain available; each LLD or Service question samples a connected neighborhood around a random component or service, and each HLD question samples a complete service path. Feedback ratings and notes do not adapt generation yet. |
| Runtime and distribution | Local browser app on Node.js 20+; optional macOS/Windows installers acquire user-local Node 24.22.1/npm. Git is required separately. | Installers require macOS 13.5+ Apple Silicon/Intel x64, Windows 10+ x64, or Windows 11 ARM64 x64 emulation. PowerShell and organization policy can block unsigned scripts; installers do not bypass policy. Direct tarball/source use requires preinstalled Node/npm. Remote models can receive repository evidence; local app execution alone does not imply local inference. |

JavaScript and TypeScript loader calls require a direct string literal as their first argument. Computed module names do not prove a dependency.

Bindings named `require` suppress calls in their lexical scope, including function parameters, hoisted variables, block declarations, loops, catch patterns and TypeScript runtime declarations. Named function and class expressions do not shadow outer calls, and type-only declarations do not create runtime bindings. Block function declarations conservatively suppress calls throughout their enclosing function because JavaScript’s non-strict hoisting rules can extend their scope.
